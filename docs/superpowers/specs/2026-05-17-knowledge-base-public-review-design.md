# 经验库公共发布与登录页经验标语设计

## 目标

本次改造解决两个问题：

1. 经验库不再按 `owner_user_id` 只展示个人私有数据，而是改成“所有登录用户可查看公共经验”。
2. 登录页增加“经验标语”区域，从经验库中随机抽取已发布条目，以短句轮播形式展示。

同时满足新的业务规则：

- 普通用户可以投稿经验。
- 管理员审核后，经验才进入公共经验库。
- 登录页只展示已发布经验，不展示待审核或驳回内容。

## 范围

本次只改以下模块：

- 后端 `gak-knowledge-base`
- 后端启动库表与种子 `gak-start/schema.sql`
- 前端 `KnowledgeBase.vue`
- 前端 `Login.vue`
- 前端经验库 API 与最小测试

不包含：

- 多级审核流
- 评论、点赞、收藏
- 登录页未登录公开接口
- 富文本编辑器

## 现状

当前后端 `KnowledgeBaseService` 有三个核心限制：

1. `page/detail/highlights` 都按 `owner_user_id = currentUserId` 查询。
2. `create/update/delete` 只允许作者本人操作，没有发布状态。
3. 登录页没有经验库入口，也没有公共短句数据源。

这导致经验库更像“个人备忘录”，而不是“公共经验池”。

## 方案选择

采用“公共发布库 + 投稿审核池”的单表扩展方案。

理由：

- 符合“普通用户投稿，管理员审核后入库”的要求。
- 在现有单表 CRUD 基础上只需补状态字段和审核动作，改造成本可控。
- 能把“公共可见内容”和“我的投稿状态”分离清楚，避免后续继续把经验库做成个人私有库。

## 数据模型设计

### 表结构扩展

在 `gak_knowledge_entry` 增加以下字段：

- `status`：经验状态，取值 `PENDING / PUBLISHED / REJECTED`
- `reviewed_by`：审核人用户 ID，可空
- `reviewed_at`：审核时间，可空
- `review_remark`：审核备注或驳回原因，可空，限制 200 字

保留现有字段：

- `owner_user_id` 继续表示投稿人
- `title/category_name/scenario/source_name/tags_text/summary/content` 不变

### 兼容策略

- 历史数据统一视为 `PUBLISHED`
- 历史数据的 `reviewed_by/reviewed_at/review_remark` 允许为空

## 后端接口设计

### 公共经验列表

现有 `GET /knowledge-base/entries` 改为按角色返回不同视图：

- 默认返回 `PUBLISHED` 条目，所有登录用户可见
- 支持可选查询参数 `view`

约定：

- `view=published`：公共经验列表，所有用户可查
- `view=my-submissions`：我的投稿，普通用户和管理员都可查自己的
- `view=pending-review`：待审核列表，仅管理员可查

如果不传 `view`，默认等同于 `published`

### 经验详情

`GET /knowledge-base/entries/{id}`

- 已发布条目：所有登录用户可见
- 待审核/已驳回条目：仅作者本人和管理员可见

### 投稿创建

`POST /knowledge-base/entries`

- 普通用户创建时写入 `PENDING`
- 管理员创建时直接写入 `PUBLISHED`
- 服务端补齐 `owner_user_id`

### 编辑

`PUT /knowledge-base/entries/{id}`

- 普通用户只能编辑自己的 `PENDING` 或 `REJECTED` 投稿
- 普通用户编辑后统一重置为 `PENDING`
- 管理员可编辑任意条目
- 管理员编辑已发布内容时保持 `PUBLISHED`

### 删除

`DELETE /knowledge-base/entries/{id}`

- 普通用户只能删除自己的未发布投稿
- 管理员可删除任意条目

### 审核接口

新增管理员接口：

- `PUT /knowledge-base/entries/{id}/publish`
- `PUT /knowledge-base/entries/{id}/reject`

请求体：

- `reviewRemark`

规则：

- 发布时设置 `status=PUBLISHED`
- 驳回时设置 `status=REJECTED`
- 两者都写入 `reviewed_by/reviewed_at/review_remark`

### 登录页经验标语接口

现有 `GET /knowledge-base/highlights` 改为：

- 只从 `PUBLISHED` 条目中随机抽取
- 支持 `size`
- 默认用于登录页与经验库页公共推荐

返回建议补充轻量字段即可，无需单独新建 VO：

- `id`
- `title`
- `summary`
- `category`
- `scenario`

## 后端权限与规则

### 普通用户

- 可查看已发布经验
- 可查看自己的待审核/驳回投稿
- 可新建投稿
- 可编辑自己的未发布投稿
- 不可审核

### 管理员

- 可查看全部已发布内容
- 可查看待审核列表
- 可审核发布/驳回
- 可编辑、删除任意条目

## 前端经验库页面设计

### 页面结构

经验库首页改成三段式：

1. 公共经验推荐
2. 公共经验列表
3. 角色相关操作区

角色相关操作区规则：

- 普通用户：展示“投稿经验”按钮和“我的投稿”分页列表
- 管理员：额外展示“待审核投稿”列表与审核动作

### 文案调整

- “新增经验” 改为 “投稿经验”
- “经验列表” 改为 “公共经验库”
- 审核状态使用清晰中文标签：`待审核 / 已发布 / 已驳回`

### 交互

- 普通用户投稿后，给出“已提交审核”的页内反馈
- 驳回条目在“我的投稿”里显示驳回原因
- 管理员在待审核卡片中可直接“通过发布 / 驳回”

### 视觉方向

沿用现有玻璃深色风格，但把信息层级收紧：

- 公共经验为主
- 投稿状态为辅
- 管理员审核区使用明显但不抢主视觉的状态色

不新增突兀大 banner。

## 登录页经验标语设计

### 位置

放在登录页左侧品牌区，与系统名称和副标题组合成一组纵向内容。

### 表现形式

采用轻量轮播短句区，而不是卡片广告：

- 标题：`今日经验`
- 主文案：经验标题
- 辅助文案：一行摘要，长度受限
- 提供“换一句”按钮
- 自动轮播，间隔 6-8 秒

### 数据规则

- 只展示已发布经验
- 为空时直接隐藏该区域，不影响登录表单
- 接口失败时静默降级，不阻塞登录

## 前端状态拆分

遵循当前仓库规范，避免一个响应式对象承载全部状态。

经验库页至少拆成：

- 公共列表状态
- 我的投稿状态
- 待审核列表状态
- 编辑弹窗状态
- 详情弹窗状态

登录页增加：

- 经验标语列表状态
- 当前展示索引
- 自动轮播计时器

## 风险与控制

### 风险 1：历史数据不可见

如果历史数据不补状态，公共列表可能为空。

控制：

- schema 初始化时给历史数据补 `PUBLISHED`

### 风险 2：普通用户误改已发布内容

控制：

- 普通用户只允许编辑自己的未发布投稿
- 已发布公共经验只允许管理员修订

### 风险 3：登录页视觉过重

控制：

- 登录页只做短句轮播，不做大卡片
- 数据为空或失败时直接隐藏，不出现空壳区块

5. 登录页接入随机经验短句
